## Disclosed methodology limitation (real, not hypothetical — same class as the Storyblocks precedent, one degree worse)

This environment's PDF tooling (`pdftotext`, present; `pdftoppm`/OCR/`pdfinfo`, absent) could not extract any clause text OR internal metadata from these four files — they are rasterized page-image captures with metadata stored in a form plain-text scanning cannot recover either. **No clause text, title, or internal date from any of these four documents has been read, quoted, or verified by the CLI as of this manifest's creation.** The LK-58 task's own §8 "Important evidence observations to verify" list — describing an All Media License, a Digital License, an Editorial Content section requiring Pond5's express/specific written consent for named commercial contexts, and a limitation-of-responsibility clause for Editorial Content — is **detailed and specific enough to plausibly reflect a real human reading**, but this manifest does not treat it as HUMAN-VERIFIED SOURCE FACT, because the supplying task explicitly instructed the CLI to perform verification the CLI's own tooling cannot perform, rather than asserting (as the LK-49 Storyblocks precedent's own task text did) that a human had already directly read the rendered captures and was reporting confirmed findings. Any characterization of these documents' substantive content must be treated as **unverified** until either (a) an explicit human confirmation that they personally read these exact preserved files (SHA-256 above) and the §8 observations are accurate, or (b) a working extraction path (page rendering + visual read, or OCR) becomes available in this environment.
