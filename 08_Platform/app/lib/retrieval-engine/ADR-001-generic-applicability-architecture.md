# ADR-001: Generic applicability is a bounded, three-valued, shallow-disjunction fact-evaluation model — never a general rules engine, never a legal-role or output-use conclusion

**Status:** Accepted — **ARCHITECTURE CONCURRED, IMPLEMENTATION NOT AUTHORIZED.** Frozen 2026-09-13, following the EU AI Act Article 50(4) CRC Publication Review (`CPR_026`) and the two generic-applicability diagnostics it prompted. This ADR records the PM-concurred *shape* of a future generic applicability architecture. It does not implement any part of it. No code, type, fixture, or schema in this repository is changed by this ADR.

**Amendment (2026-09-15) — Generic Shallow Applicability Expression Contract, PM Freeze.** Following a read-only investigation (Generic Shallow Applicability Expression Contract) and this PM Freeze Amendment, the remaining open decisions this ADR's own §C/§D flagged as "still open" for the *shallow-disjunction field itself* (never for the organization-geography fact name or the distribution-territory `ApplicabilityFact` name, both of which remain open exactly as before) are now frozen: the production field name (§K.1), structural validity for that field (§K.2), the invalid-governance-vs-unresolved-project distinction and its smallest safe representation (§K.3), the valid-expression AND/OR algebra restated as the final frozen form (§K.4), material-unresolved semantics generalized to the mandatory-AND-group-plus-alternative-AND-groups shape (§K.5), the authoritative evaluator output contract (§K.6), the per-consumer policy-preservation principle (§K.7), and the governance-enforcement point (§K.8). **Still IMPLEMENTATION NOT AUTHORIZED** — this amendment freezes decisions only; no code, type, fixture, test, or migration exists yet. **No runtime code, type, fixture, or Article 50 state was changed by this amendment** — Article 50 remains exactly as §F below states (`crc_eligible: Pending` on both the claim and the relationship; `CPR_026`'s WITHHOLD disposition fully authoritative and unchanged; onboarding PAUSED). See §K for the full frozen text.

**Date:** 2026-09-13

**Context:** `CPR_026` withheld CRC publication for `CLAIM-EUAI-ART50-4-AUDIOVISUAL-DEEPFAKE-DISCLOSURE-001-v1` on a narrow, non-Principle-3 ground: the claim's empty `applicability_requirements` array gives it unrestricted global retrieval reach once eligible. `CPR_026`'s own proposed remedy — `applicability_requirements: [{fact:'jurisdiction', operator:'equals', value:'European Union'}]` — was independently found superseded: `jurisdiction`/`AssessmentJurisdictionMention` represents "the jurisdiction the user asked CRC to consider," not organization establishment, not distribution territory, not output-use. A faithful representation of Article 2(1)(b)/(c) ("established in the Union" OR "output used in the Union") requires (a) a fact type this codebase does not yet have (organization/establishment geography) and (b) a boolean capability this codebase's `applicability_requirements` array does not have (disjunction — the current model is a flat, AND-only array). This ADR states the durable, generic principle a future implementation must be checked against; it is deliberately not Article-50-specific.

**Relationship to existing architecture:** Extends, without contradicting, `lib/retrieval-engine/lookup-topic-claims.ts`'s own existing `isApplicable`/`evaluateRequirementStatus` three-state (`met`/`not_met`/`unresolved`) discipline, and `lib/bounded-interpretation/build-bounded-interpretation.ts`'s existing Case 3A/3B distinction between a settled exclusion and an open, hedge-worthy question. Nothing in this ADR authorizes weakening either.

**Applies to:** `lib/retrieval-engine/**` (the applicability evaluator and its consumers — `lookupTopicClaims`, `lookupRelatedTopicClaims`), any future `TopicClaim` whose real-world applicability is disjunctive across independently-sufficient conditions, and any future Structured Understanding fact proposed to represent organization/actor geography. Does **not** apply to, and does not authorize any change to, `GOAL_CATEGORIES`, `KNOWLEDGE_ONLY_TOPICS`, Retrieval's topic-matching logic, Track A discovery (`geographic_relevance_scope`), Bounded Interpretation's composition logic, or any production fixture.

## Decision

**A. Decisions approved now**

1. **Shallow-disjunction expression model (Decision 1).** The target semantic capability is: a leaf condition; an AND of leaves (today's existing flat array, unchanged); an OR of AND-groups; optionally, the existing flat requirements combined with one shallow OR-group structure. Shape: `applicability_requirements: ApplicabilityRequirement[]` (unchanged) plus an additive `applicability_any_of?: ApplicabilityRequirement[][]` (name FROZEN 2026-09-15 — see §C/§K.1). **No arbitrary recursive expression tree. No arbitrary nesting depth beyond this one shallow OR-of-ANDs level. No general `NOT` operator. No arithmetic or cross-fact inference. Not a general-purpose rules engine.**

2. **Three-state aggregation is preserved through composition (Decision 2).** `met`/`not_met`/`unresolved` remain the complete status vocabulary. Group aggregation follows standard three-valued (Kleene strong) logic — the unique minimal generalization consistent with existing behavior, not invented ad hoc:
   - **AND-group:** `not_met` if any child is `not_met`; else `unresolved` if any child is `unresolved`; else `met` only if all children are `met`.
   - **OR-group:** `met` if any child is `met`; else `unresolved` if any child is `unresolved`; else `not_met` only if all children are `not_met`.
   - Worked examples (frozen): `OR(UNRESOLVED, MET) = MET`. `OR(UNRESOLVED, NOT_MET) = UNRESOLVED`. `AND(UNRESOLVED, MET) = UNRESOLVED`. `AND(UNRESOLVED, NOT_MET) = NOT_MET`.
   - **Known-false must never be represented as unresolved, in either direction of composition.** A future implementation must preserve `build-bounded-interpretation.ts`'s existing distinction — read directly from that file's own `collectUnresolvedRelevantClaimIds` doc comment — between a settled exclusion (`not_met`, silently excluded, never surfaced) and unresolved applicability requiring the Case 3B hedge (surfaced, hedged, never a false-positive "relevant" and never a false-negative "irrelevant").

3. **Organization observational fact class approved, type name not frozen (Decision 3).** CRC needs a user-attested, observational fact describing where an organization/company is based, established, located, or equivalent — reusing the existing supersede-and-mark correction pattern (`superseded_by`) already proven by `AssessmentJurisdictionMention` and `DistributionTerritoryMention`. This fact **must not** itself assert legal establishment under any statute, deployer status, provider status, duty-holder status, jurisdictional applicability, or compliance — it preserves the user's factual statement, never converts it into a legal characterization. See §J for the recommended name.

4. **`DistributionTerritoryMention` approved as a future applicability-capable fact source, its evidentiary meaning for any specific statutory pathway NOT decided (Decision 4).** The generic architecture may make distribution territory consumable by `isApplicable` (a new `ApplicabilityFact` value reading the existing mention collection — the type itself needs no change). Whether a *stated/intended* distribution territory is close enough to Article 2(1)(c)'s *actual* "output... is used in the Union" to govern that specific pathway is an **unresolved, separate, future governed-claim-mapping decision** — not decided here, and not decidable by architecture alone (see §D).

5. **No legal-role self-attestation, reaffirmed (Decision 5).** A bounded observational question ("Where is your organization based?") is askable when governed knowledge creates a legitimate need for it, via the existing eligibility-gate pattern `jurisdiction-clarification.ts` already establishes (fires only when an active, confirmed goal resolves — directly or one relationship-hop — to an Adopted+CRC-eligible claim carrying the fact as a requirement; never proactive in the absence of such a claim). **"Are you a deployer under the EU AI Act?" or any equivalent legal-role self-classification question must never be asked.** `deployer_status_confirmed` remains evidence-only/unresolved under the existing Stock Governance Rule, permanently, regardless of whether organization location becomes known. Organization location and deployer status are never conflated, never merged into one fact, never merged into one question.

6. **Revised sequencing (Decision 6).** The generic architecture (fact representation, expression model, bounded askability) and a dormant Article 50 fixture migration to the faithful applicability shape may be implemented and validated while `crc_eligible` remains `Pending` — **this does not need to be atomic with a CRC Publication decision.** Preferred sequence: (1) record this architecture concurrence [this ADR]; (2) implement generic fact representation; (3) implement the shallow applicability expression; (4) implement bounded askability only where governed knowledge requires it; (5) separately authorize and migrate the dormant Article 50 claim to the faithful representation; (6) validate the dormant representation end-to-end; (7) conduct a fresh CRC Publication Review; (8) only then make an independent `crc_eligible` decision; (9) activation remains subject to every existing gate (double-gate, Bounded Interpretation, Stock Governance Rule, etc.). No downstream layer may create a stronger conclusion than Bounded Interpretation permits, at any step of this sequence.

**B. Exact semantics frozen now** — §A.2's three-valued aggregation rules (AND/OR, the four worked examples) are frozen as the durable principle. §A.1's shallow-disjunction *shape* (leaf → AND-group → shallow OR-of-AND-groups, backward compatible with the existing flat array) is frozen. Nothing about field names, exact TypeScript shapes, or file locations is frozen.

**C. Naming — partially resolved 2026-09-15 (§K.1)** — The shallow-disjunction field's exact production name is now FROZEN: `applicability_any_of?: ApplicabilityRequirement[][]` (§K.1). Still open, unchanged by this amendment: the organization-geography fact's exact type name — see §J for this ADR's own recommendation, offered but not frozen — and the `distribution_territory`-style `ApplicabilityFact` value's exact name.

**D. Article-50-specific mapping still open** — Whether/how `CLAIM-EUAI-ART50-4-AUDIOVISUAL-DEEPFAKE-DISCLOSURE-001-v1`'s own production `applicability_requirements` should eventually be authored using this architecture. Whether a stated distribution territory is a sufficient evidentiary proxy for Article 2(1)(c)'s "output... used in the Union" (Decision 4) — this is a **future, separately-governed, claim-specific applicability-mapping decision**, not resolved by approving the generic mechanism. This ADR does not conclude that Article 2 applicability has been resolved, that organization location proves legal establishment, that intended distribution proves actual output use, that the user is a deployer, that Article 50 applies to any project, or that the claim is CRC-publishable.

**E. Implementation not yet authorized by this artifact** — No fact type, extraction candidate kind, `ApplicabilityFact` value, evaluator branch, or schema field is created by this ADR. §A.6's sequence step (2)-(6) remain future, separately-authorized engineering milestones.

**K. PM Freeze Amendment (2026-09-15) — Generic Shallow Applicability Expression Contract.** Resolves the remaining open decisions this ADR left open for the shallow-disjunction field itself (never for the organization-geography fact or the distribution-territory `ApplicabilityFact` value, both still open per §C). Derived from re-reading current production source directly (`lib/retrieval-engine/types.ts`, `lookup-topic-claims.ts`, `applicability-readiness.ts`, `retrieve.ts`, `lib/crc-engine/selector-askability.ts`/`selector-questioning.ts`, `lib/bounded-interpretation/types.ts`/`build-bounded-interpretation.ts`, `lib/hrr/bi-adapters.ts`) — never derived from, or fitted to, Article 50, which remains cited only as the original motivating boundary evidence (§ this ADR's own Context above).

1. **Frozen production field name.** `applicability_any_of?: ApplicabilityRequirement[][]`, additive on both `TopicClaim` and `MatrixClaim`, adjacent to (never replacing) `applicability_requirements`. `applicability_requirements` = the mandatory AND-group, unchanged in meaning. `applicability_any_of` = an optional OR of AND-groups. Combined valid-expression aggregate = `AND(mandatory_aggregate, alternatives_aggregate)` (§K.4). Absent → alternatives contribute `met`/no-op → byte-identical to today's existing behavior for every current claim. No expression object, no recursive AST — `T[][]` is structurally as deep as this schema can ever go.

2. **Frozen structural validity.** Valid: field absent; field present with ≥1 group; every group containing ≥1 syntactically well-formed `ApplicabilityRequirement` (known `fact` ∈ `APPLICABILITY_FACTS`, a supported `operator`). Invalid governed knowledge (never authorable, per §K.8's enforcement point): `applicability_any_of: []` (empty outer array); any empty inner group; a malformed requirement (missing/wrong-typed `fact`/`operator`/`value`); an unknown `ApplicabilityFact` value; an unsupported operator; any structurally invalid nested content (a third array level, a non-array group, etc.). Duplicate requirements and duplicate groups remain semantically valid and idempotent (`AND(x,x)=x`, `OR(x,x)=x`) — hygiene diagnostics only, never a validation failure.

3. **Invalid governed applicability vs. unresolved project fact — normative, and structurally separate.** `unresolved` means: the governed expression is valid, but currently-available project facts do not yet determine its applicability — the normal, user-actionable state Track B may ask about. It must never mean the expression itself is malformed or unsupported. **Invalid governed applicability is not a fourth value of the `met`/`not_met`/`unresolved` state — current architecture proves no fourth state is required**, because validity is checked at a structurally earlier, separate gate than evaluation: a claim's `applicability_any_of` (and `applicability_requirements`) is validated (§K.8) *before* the three-valued evaluator ever runs on it, exactly mirroring how a genuinely malformed object cannot compile against the existing TypeScript-typed fixture files today. The smallest implementation-safe representation is therefore a validation step whose own output is orthogonal to the state enum — a pass/fail (or `violations: string[]`) result gating whether evaluation happens at all — never an additional member of `ApplicabilityRequirementStatus`/the aggregate `status` union. Defense-in-depth (invalid data somehow reaching the evaluator anyway): the claim is excluded from candidacy exactly as a settled `not_met` claim already is today (silent to the retrieval result, loudly logged for engineering — mirroring this codebase's own established "silent to the user, loud in logs" discipline elsewhere), via a diagnostic reason distinct from `applicability_unmet` so it can never be fed into `unresolvedRequirementsIfClaimStillEligible`/materiality/Track B alongside genuine per-requirement outcomes. It must never surface as a `RetrievalDiagnostic{reason:'applicability_unmet'}` (which could become a Track B question), never as an ordinary `unresolved_project_dependencies` string, and never silently reinterpreted as `met` or `not_met` by any downstream layer.

4. **Frozen valid-expression algebra** (restates and finalizes §A.2's worked examples as the complete tables; applies only to structurally valid expressions per §K.2/§K.3):

   AND: `MET+MET=MET` · `MET+UNRESOLVED=UNRESOLVED` · `MET+NOT_MET=NOT_MET` · `UNRESOLVED+UNRESOLVED=UNRESOLVED` · `UNRESOLVED+NOT_MET=NOT_MET` · `NOT_MET+NOT_MET=NOT_MET`.

   OR: `MET+MET=MET` · `MET+NOT_MET=MET` · `MET+UNRESOLVED=MET` · `NOT_MET+NOT_MET=NOT_MET` · `NOT_MET+UNRESOLVED=UNRESOLVED` · `UNRESOLVED+UNRESOLVED=UNRESOLVED`.

   No domain-specific exceptions of any kind.

5. **Frozen material-unresolved semantics.** `applicability_requirements` is itself treated as one AND-group for materiality purposes (unchanged from today). A given `unresolved` leaf is material if and only if BOTH: (a) the complete valid-expression aggregate (`AND(mandatory, alternatives)`) is `UNRESOLVED`; and (b) the leaf's own immediate AND-group carries no `NOT_MET` leaf (the group remains "live"). Nothing is material once the aggregate has already resolved to `MET` or `NOT_MET` by any pathway. Verified against every combination this amendment's own task posed, including the two paired examples that must resolve oppositely (`(A unresolved AND B met) OR (C met)` type cases where a still-live alternative leaves a mandatory leaf material vs. a case where a dead mandatory group forecloses it entirely, and `(B unresolved AND C not_met) OR (D unresolved)` where B is correctly non-material because its own group is dead while D is material) — this is a direct generalization of, not a departure from, `selector-questioning.ts`'s existing `unresolvedRequirementsIfClaimStillEligible`. The evaluator/materiality layer alone owns this computation; Track B, Bounded Interpretation, Projection, and Composition must never recompute it.

6. **Frozen authoritative evaluator output.** For a structurally valid expression, the evaluator's output MUST contain exactly one authoritative field, `status: 'met' | 'not_met' | 'unresolved'`, plus one centrally-derived material-unresolved-dependency list (§K.5's output — a flat, group-agnostic `ApplicabilityRequirement[]`-shaped list, mirroring `BiApplicability.unresolved_requirements`'s existing shape exactly). Per-leaf/per-group diagnostic detail may additionally exist for provenance/debugging/display (e.g. `applicability-fact-display.ts`'s per-`ApplicabilityFact` label lookup) but is explicitly NON-AUTHORITATIVE — every downstream consumer MUST treat `status` as sole applicability authority and the material list as the sole unresolved-dependency source, and MUST NOT rescan diagnostic leaves to (re)derive either.

7. **Frozen consumer-policy-preservation principle — no new universal Retrieval policy.** This amendment does not freeze a single blanket rule ("aggregate !== met ⇒ always exclude") replacing every consumer's own behavior. It freezes only that (i) the evaluator alone determines the authoritative `status`/material list, (ii) each existing consumer keeps its own current policy toward `met`/`not_met`/`unresolved`, now driven by that authoritative output instead of ad hoc flat-leaf scanning, and (iii) no consumer may independently interpret `applicability_any_of`'s OR/AND structure. Current per-consumer policy to be preserved verbatim by any future implementation:
   - **CRC retrieval** (`lookupTopicClaims`, `retrieve.ts`'s Matrix path): only `status === 'met'` → included in `matches[]`; both `not_met` and `unresolved` → excluded, `RetrievalDiagnostic{reason:'applicability_unmet'}` emitted. Unchanged — this consumer has never distinguished `not_met` from `unresolved` for inclusion purposes and continues not to.
   - **Reviewer/HRR research** (`lib/reviewer-lk/select-reviewer-claims.ts` → `lib/hrr/bi-adapters.ts`'s `reviewerClaimToBiResult`): `met` → `BiApplicability{status:'established'}`; `unresolved` → surfaced with the hedge, `unresolved_requirements` populated from the material list; `not_met` → excluded from the BI feed entirely by the caller, routed to `does_not_apply[]`. This is the one consumer whose behavior actually depends on the `not_met`/`unresolved` distinction — preserved exactly.
   - **Track B / selector questioning** (`selector-questioning.ts`): a claim contributes a candidate need only from its own material-unresolved leaves (§K.5), gated further by `selector-askability.ts`'s existing fail-closed-by-default registry and `BoundaryState`'s existing dedupe/cap discipline — unchanged.

8. **Frozen governance-enforcement point.** Reuses the existing three-layer scheme that already governs every other `TopicClaim`/`MatrixClaim` field — TypeScript literal-type discipline on hand-authored fixture files, human FGR/CPR governance review, and a test-time consistency guard (extending `topic-claims-fixture-consistency.test.ts`'s own established discipline with one new structural test covering §K.2's invariants) — never a new runtime schema-validation layer, since no runtime-loaded/user-submitted `TopicClaim` path exists anywhere in this codebase today. No Article-50-specific validation is introduced or implied. Defense-in-depth at the evaluator's own entry point (§K.3) remains fail-closed even if invalid governed data somehow escapes authoring-time validation. `Lifecycle`/`crc_eligible`/`provider_scope`/`tool_scope` remain untouched, separate, already-authoritative gates, exactly as `provider_scope`'s own doc comment already establishes for this codebase's other scope fields.

9. **Reaffirms §E/§F/§D unchanged.** Implementation remains NOT AUTHORIZED by this amendment — no code, type, schema field, extraction candidate, or fixture is created or altered. `CLAIM-EUAI-ART50-4-AUDIOVISUAL-DEEPFAKE-DISCLOSURE-001-v1` and `REL-COMMERCIAL-USE-AI-CONTENT-TRANSPARENCY-v1` both remain `crc_eligible: Pending`; `CPR_026`'s WITHHOLD disposition remains fully authoritative; Article 50 onboarding remains PAUSED. This amendment does not decide, and does not imply a decision on, Article 2 evidence sufficiency, `OrganizationLocationMention`'s or `DistributionTerritoryMention`'s mapping onto Article 50, or any claim-specific applicability authoring (§D, unchanged).

## What this ADR explicitly preserves

- **Living Knowledge governance authority** — Adoption, CRC Publication, and runtime activation remain three distinct, sequential decision stages (per `governance-reviews/README.md`'s own three-artifact-type discipline); this ADR is none of the three, it is an architecture-shape concurrence that precedes future instances of all three.
- **Retrieval vs. Bounded Interpretation separation** — the applicability evaluator (`isApplicable`) only ever produces an inclusion/exclusion signal for `matches[]`; Bounded Interpretation consumes only a claim's own governed text plus the `unresolved`/`not_met` status already computed for it, never raw fact values. This ADR adds richer *input* to that boundary; it does not move the boundary.
- **Explicit goals vs. discovered relevance** — nothing in this ADR touches `GOAL_CATEGORIES`, `UserGoal` construction, or Track A's `geographic_relevance_scope`/`territoryRelevanceMatches` mechanism, confirmed structurally independent of `isApplicable` by direct code inspection.
- **Track C provenance** — `sourceGoalCategory`/`matched_goal_category` stamping is computed independently of `isApplicable`'s result; an expanded applicability model changes only whether a claim is included, never which goal category it is attributed to.
- **Fail-closed applicability** — an unaddressed fact remains `unresolved`, never guessed; a genuinely excluded fact remains `not_met`, never silently reclassified as `unresolved`. §A.2 is a direct, minimal extension of this existing discipline, not a departure from it.
- **Correction semantics** — the organization-geography fact reuses the proven supersede-and-mark pattern verbatim; a future evaluator branch reading it must filter to `superseded_by === null` before deriving included/excluded values, exactly mirroring `deriveAssessmentJurisdictionFacts`'s own `currentMentions()` filter, so a corrected value can never continue satisfying a group.
- **Bounded questioning** — the organization-geography fact is askable only when a real, governed, eligible claim creates the need (mirroring `jurisdiction-clarification.ts`'s own eligibility gate), never proactively, never as a generic onboarding question.
- **Stock Governance Rule** — no legal-characterization or legal-role question (`deployer_status_confirmed`, `content_constitutes_deep_fake`, or any future equivalent) becomes a direct self-attestation question merely because a related observational fact becomes representable.
- **No fabricated legal conclusions** — the architecture answers only "is this claim a retrieval candidate for this project state," never "does this law apply," "is this party a deployer," "is this content a deep fake," or "is this project cleared."

## Why (the problem this prevents)

Without this stated principle, a future fix to a reach problem like `CPR_026`'s could plausibly:

- reuse the nearest existing fact (`jurisdiction`) because it is already wired, silently misrepresenting what the user actually told CRC (exactly `CPR_026`'s own original, now-superseded, proposed remedy);
- collapse two independently-sufficient statutory conditions (establishment, output-use) into one blended "territorial nexus" fact, producing a false result for a project that satisfies exactly one condition but not the other;
- build an unbounded recursive boolean-expression engine "while we're at it," turning a narrow, disclosed representation gap into a general-purpose rules engine with an unbounded testing and authoring surface;
- collapse `not_met` and `unresolved` at the group level, turning a known-false exclusion into an open question (or vice versa) the moment aggregation is introduced;
- ask a user directly whether they are a "deployer," manufacturing an unqualified legal self-classification CRC then treats as dispositive;
- treat *intended* distribution territory as *actual* output use without disclosing the gap, silently strengthening a hedged fact into a stronger-than-warranted applicability conclusion.

Each of these would either misrepresent governed law, weaken the existing fail-closed guarantee, or expand scope into a general-purpose inference engine this codebase's own `APPLICABILITY_FACTS` doc comment (Phase 1) already explicitly declined to become. This ADR names the boundary so a future implementation, and any later domain needing the same shape (§ genericity, `CPR_026`-diagnostic Cases A-H), can be checked against one stated principle rather than reconstructed ad hoc.

## Consequences

**Positive:**
- A future Article 50 fixture migration, and any future claim needing an establishment-OR-output-use (or structurally similar) applicability shape, has one stated architectural boundary to design against.
- The three-valued aggregation rule is reusable verbatim by any future disjunctive claim — no per-domain semantics need to be re-derived.
- The organization-geography fact, once implemented under this ADR's naming discipline (§J), becomes reusable by any future domain needing organization-location evidence — not an Article-50-only artifact.
- `CPR_026`'s own safety finding is honored and its remedy cleanly superseded (see addendum) without reopening or weakening its WITHHOLD disposition.

**Costs/limits:**
- The shallow-disjunction model deliberately cannot represent an Article-2-shaped rule nested two levels deep (e.g., `(A OR B) AND (C OR D)`); no such case is currently known in this corpus, and extending the model further should require its own ADR, not a silent generalization.
- Distribution-territory-as-output-use-evidence remains an open, disclosed compromise (§D) — a future claim using it must carry its own bounded wording disclosing "stated," never asserting "actual," exactly as `CPR_026`'s own §I finding already required for a cruder version of the same fact.
- This ADR intentionally left naming and exact schema shape open at first (§C); the shallow-disjunction field's own name and structural-validity/algebra/materiality/enforcement decisions are now frozen (§K), while the organization-geography fact name and the distribution-territory `ApplicabilityFact` name remain open — a future implementation milestone must still make those two calls; this is a deliberate, disclosed incompleteness, not an oversight.

## Enforcement

**Not yet in place** — no code exists yet. A future implementation should add: a source-scan/architecture test confirming no `NOT` operator, no nesting beyond one `any_of` level, and no new `ApplicabilityFact` value bypasses the three-valued aggregation rule; a scratch/unit-test suite proving the four worked examples (§A.2) exactly, extended per §K.4's final tables; the §K.2/§K.8 structural-validity test (empty-array, empty-group, unknown-fact, malformed-requirement, duplicate-hygiene checks); and a correction test proving a superseded organization-geography mention can never continue satisfying a group (mirroring the existing `AssessmentJurisdictionMention`/`DistributionTerritoryMention` correction test precedent). None of this is implemented by this ADR or by its 2026-09-15 amendment (§K) — both remain documentation/decision artifacts only.
