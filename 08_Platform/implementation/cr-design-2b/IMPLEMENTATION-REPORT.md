2. **Long content.** Keep-together is bounded (650 characters); longer content breaks between parts. No fixed page lengths, clipping or oversized unbreakable views (react-pdf warnings captured: 0 in all 13 cases).
3. **D10.** Unchanged. No reading text enters the guidance, index or caveat panel; readings print only in section 6 on reading-register pages; the `readiness_layout_refused` guards still refuse.
4. **Navigation copies.** Recorded in `model.navigation_copies` (declared title and its question; caveat pointers). Tests exclude exactly these and the C-1 heading, and require every other block to print once, as under v4/v5.

## 5. Findings for review

1. **P3 cannot exist as specified.** A record with no reading is always schema 7, so "schema 8 with no added documents" is not producible; the document-free case is P1. P3 shows the closest real schema 8 case.
2. **Failed readings never reach a record** (by design), so reading-failure labels print only for replayed readings; P10 shows a document whose reading failed as "not examined".
3. **Text layer: curly apostrophes.** In 8 of 13 PDFs, some strings containing "’" extract incorrectly (copy/search/assistive technology); the printed page is correct. The same defect already affects today's v4/v5 output for 2 of 13 records. Two causes in the new fonts (substitutions, duplicate PostScript names) were found and fixed; the remaining one sits in the PDF library's subsetting. Recommend a follow-up before release; tagged PDF/UA remains deferred.
4. **Visual items for the reviewers:** the CJK title prints in the fallback face beside Fraunces (expected); the first page can end with space when the "What you told us" panel moves to page 2; long consideration and document cards continue across pages without a "(continued)" header (deferred).
